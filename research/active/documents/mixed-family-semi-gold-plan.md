# Mixed-Family Semi-Gold Plan

## Status

- Status: active
- Scope: `research/` semi-gold follow-on after `P1 hard-transition micro-pack`
- Audience: researchers, platform engineers, AI agents
- Last updated: 2026-04-04

## Purpose

This document defines the first repository-backed `semi-gold` follow-on after:

- `compositional-mixed-family-gold-first-phase2`
- `compositional-mixed-family-gold-first-hard`
- `P1 hard-transition micro-pack`

The key methodological change is deliberate:

> the trusted intermediate layer is no longer fully gold.

Instead, one intermediate is now:

1. generated by the model,
2. verified by the same Hilbert kernel,
3. promoted to a reusable artifact,
4. imported by the final stage together with the remaining gold lemmas.

This is a protocol change, not just a harder CSV.

## Guardrail

These surfaces do **not** replace the cleaner `gold-first` claim surfaces.

- `gold-first` remains the canonical clean line for fully trusted imported lemmas
- `semi-gold` is a next-layer protocol probe
- success or failure here must not be back-projected onto `gold-first`

## P2A

### Command surface

- `researchctl compositional-mixed-family-semi-gold-stable`

### Input pack

- `cases/compositional-mixed-family-semi-gold-stable.csv`

### Intent

`P2A` asks the narrow question:

> does the line survive replacing one gold intermediate with one verifier-approved model-generated bridge on the already stable axis?

This surface is intentionally biased toward the geometry where `gpt-oss:120b-cloud`
and `deepseek-v3.1:671b-cloud` were already strong in the fully-gold setting.

### Shape

Each chain contains:

1. `m1` — verifier-approved model bridge
2. `fm` — final semi-gold composition step
3. `neg` — hard negative twin on the same import layer

## P2B

### Command surface

- `researchctl compositional-mixed-family-semi-gold-frontier`

### Input pack

- `cases/compositional-mixed-family-semi-gold-frontier.csv`

### Intent

`P2B` asks the frontier question:

> does the line still hold when the trusted layer is not fully gold and the transition already sits on the hard frontier?

This surface deliberately targets:

- low symbol overlap
- merge-style imports
- bridge-depth-1 frontier geometry
- GMFH13-like hard entailed transitions

### Shape

Each chain contains:

1. `m1` — verifier-approved model bridge
2. `fm` — final semi-gold frontier composition
3. `neg` — hard negative twin on the same import layer

## Important interpretation rule

Unlike the `gold-first` runnable surfaces, `semi-gold` necessarily includes an
executed bridge stage.

That does **not** make the design semantically dirty in the same way as the old
starter compositional lanes, because here:

- the bridge stage is the point of the protocol;
- the bridge is explicitly verifier-confirmed before reuse;
- the final stage imports a named prior artifact rather than relying on an
  untracked starter assumption.
